SLIDE 1 (title)
A method is a named block of code that you can call many times. Today you will learn how to define a method, how to call it, how to pass in parameters, and how to get a value back with the return keyword. You will also take a first look at method overloading. By the end of this lesson, you will know how to split a program into small, clear pieces that are easy to read and easy to fix.

SLIDE 2 (what is a method)
Think about a recipe. You write the steps once, and then you can follow them every time you want that dish. A method works the same way. You give a block of code a name, and then you call that name whenever you need the code to run. Methods keep your programs organized, and they avoid repeating the same lines again and again. If you find yourself copying a block of code, that is a good sign that it should become a method. In a real program, you might have one method that calculates a tax, another that checks a password, and a third that prints a report. Each method does one job, so when something goes wrong, you know where to look. Choose names that describe the action, such as greet or add, so that anyone reading your code understands it quickly.

SLIDE 3 (defining and calling a method)
Here is a simple method. The header has the words public, static, and void. After that comes the name, which is greet in this example. The empty brackets mean this method takes no input. The body of the method sits between curly braces. Inside main, we call greet by writing its name, followed by empty brackets and a semicolon. When the program runs, the welcome message prints. The word void means the method returns nothing. The word static lets us call the method from main without creating an object first. We will explain objects later in the series. Try changing the text inside the quotes, then run the program again. If you call greet three times, the message prints three times, but you wrote the printing code only once. That is the real power of a method.

SLIDE 4 (parameters)
Parameters let you pass data into a method. Inside the brackets, you list a type and a name for each value the method needs. In this example, the method greetUser takes one String called name. When you call it, you pass a value in the brackets, such as the text Priya. Inside the method, the name variable holds that value, so the message says Hello, Priya. You can call the same method with different values, and each call gives a different result. A method can take more than one parameter too. You separate them with commas. For example, a method called greetWithAge could take a String called name and an int called age. You call it with two values, in the same order as the parameters. The parameter is a copy of the value for the length of the method. If the method changes name, the variable in main does not change, which keeps your data safe.

SLIDE 5 (return values)
Sometimes a method needs to give a result back to the code that called it. To do this, set the return type to the type of the value, such as int, and use the return keyword. In this example, the method add takes two int values, a and b. It returns their sum. In main, we store the result in a variable called total. Total holds 10, so the program prints 10. Notice that the return type is int, not void, because this method sends a whole number back to the caller. Return values are very handy inside other expressions. For example, System dot out dot println of add 2 and 3 prints 5 directly. Once a method reaches a return statement, it stops, so no code after that return in the same method will run.

SLIDE 6 (void or a return type)
Here is a quick way to check any method. If the return type is void, the method does not give a value back, so you cannot store its result in a variable. If the return type is int, String, or another type, the method must use return with a value of that type. If you forget the return statement, the compiler stops with an error message. So read the return type first. It tells you what the method gives back, if anything at all. A method with a non-void return type must return a value on every path through the code. If you use an if statement inside it, make sure every branch returns a value, or add a return at the end of the method.

SLIDE 7 (method overloading preview)
You can give two methods the same name, as long as their parameters are different. For example, one version of add can take two int values, and another version can take two double values. The compiler looks at the values you pass in, and it picks the right version for you. We will study overloading in detail in a later lesson. For now, just know that one name can work for different kinds of input. Remember that changing only the return type is not enough to overload a method. Java looks at the number of parameters and their types to decide which version to run. Overloading is useful when the same action works on different kinds of data. Think of print: you may want to print a whole number, a decimal, or a piece of text, and each version can handle its own type cleanly. You will see this idea again when we reach the standard library, because Java uses overloading in many places.

SLIDE 8 (common mistakes)
Let us look at three common mistakes. The first mistake is passing the wrong number of values. If add needs two numbers, then add with only one number will not compile. The second mistake is forgetting the brackets when you call a method. Writing greet without brackets is wrong, because you must write greet with its empty brackets. Java needs those brackets even when the method takes no input, so the compiler knows you are calling a method and not reading a variable. The third mistake is placing one method inside another method. Java does not allow that, so close the first method before you start the next one. Read the error message carefully, because it usually points you to the exact line. When you see an error, do not panic. Look at the line number, read the message, and then compare the method header with the way you called it. Most method errors come from a mismatch between the two.

SLIDE 9 (recap)
You learned how to define a method with a name and a body, how to call it, and how to pass in parameters. You also learned how to send a value back with return, and that void means no return value. Finally, you saw that overloading lets two methods share one name when their parameters differ. Tomorrow we use arrays to store many values together.
